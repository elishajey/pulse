변동 확인 EU

AI법 투명성 지침이 관보에 실렸다 — 8월 2일 전에 내놓은 생성형 AI는 12월 2일까지 기계 판독 표시를 붙여야 한다

유럽연합 관보 11월 12일자에 AI법 투명성 지침이 실렸습니다. 문서번호는 C/2026/6005입니다[T1]. 보안 담당자는 제50조 2항을 먼저 봐야 합니다. 생성형 AI 사업자는 산출물에 기계 판독 표시를 심고 그 표시를 찾아낼 검출 수단까지 함께 제공해야 합니다[T1]. 지침 제79항은 표시와 검출에 쓰는 기술 수단이 효과적이고 상호운용되며 견고하고 신뢰할 수 있어야 한다고 적었습니다[T1].

기한이 3주 남았습니다. 제50조는 8월 2일부터 적용되지만 그 전에 시장에 내놓은 생성형 AI에는 유예가 붙습니다. 제153항은 이 시스템이 2026년 12월 2일까지 표시 의무를 맞추면 된다고 정했습니다[T1]. 유예는 제50조 2항 표시 의무에만 적용되고, 대화형 기능이 섞인 시스템은 8월 2일부터 고지 의무를 그대로 집니다[T1]. 제152항의 과징금 상한은 1,500만 유로이며 기업은 전년도 전 세계 매출액 3% 중 높은 금액을 적용받습니다[T1].

국내 기업도 EU에 법인이 없어도 적용 대상이 됩니다. 지침은 역외 활용사업자라도 산출물이 EU 안에서 유통될 것을 예견할 수 있으면 범위에 들어온다고 정리했고, 대행사나 프리랜서를 써도 활용사업자 지위는 그대로라고 짚었습니다[T2]. 통신사와 플랫폼사가 EU 이용자에게 생성형 기능을 열어 두거나 현지 광고를 돌리고 있다면 공급사 모델이 심는 표시만 믿어서는 안 됩니다. 자사 서비스 단계에서 딥페이크 고지를 따로 붙여야 합니다[T2].

[elisha’s take] — EU에 생성형 기능을 열어 두고 있으면 12월 2일까지 산출물 표시와 검출 수단을 둘 다 갖췄는지 이번 주에 확인하십시오.

표시만으로는 의무를 다하지 못한다 — 제50조 2항은 기계 판독 표시와 검출 가능성을 한 쌍으로 요구합니다[T1]. 둘 중 하나만 채우면 의무 이행으로 인정되지 않습니다[T2]. 활용사업자는 공급사가 모델에 심어 둔 표시를 근거로 딥페이크 고지 의무를 갈음할 수 없습니다[T2]. 고지는 사람이 알아볼 수 있어야 하므로, 모델 수준의 워터마크와 서비스 화면의 라벨은 별개의 통제입니다[T2].

지침의 성격과 이력 — 43쪽에 155개 항으로 짜였고, 제5항이 스스로 비구속 문서임을 밝히고 있습니다[T2]. 집행위원회는 7월 20일 C(2026) 5054 final로 먼저 공개했고, 이번에 관보에 실어 인용 가능한 형태로 확정했습니다[T2]. 구속력은 없지만 감독기구가 제50조를 어떻게 읽을지를 보여 주는 기준선이라 실무 준수 설계의 출발점이 됩니다[T2].

고영향 시스템에는 유예가 겹치지 않는다 — 각주 50은 제111조 2항을 가리키며, 고영향 AI 시스템이 제50조 의무도 함께 지는 경우에는 그 특례가 적용되지 않는다고 적었습니다[T1]. 고영향 분류 지침 자체는 아직 초안 단계이고 집행위원회는 연내 채택을 목표로 두고 있습니다[T3]. 12월 2일 유예를 믿고 일정을 미루려면 해당 기능이 고영향 분류에 해당하지 않는지 먼저 확정해야 합니다[T2].

역외 적용과 제외 범위 — 광고 대행만 맡기고 AI 사용 방식을 통제하지 않는 발주 기업은 활용사업자가 아닙니다[T2]. 타인의 AI 콘텐츠를 전달만 하는 호스팅 서비스와 플랫폼도 활용사업자가 아니지만, 자사 마케팅에 AI를 쓰는 초대형 온라인 플랫폼은 활용사업자가 됩니다[T2]. 제품을 실제보다 좋아 보이게 만든 AI 제품 이미지는 딥페이크로 분류됩니다[T2]. 반면 AI로 손본 광고 문구와 제품 설명은 건강·소비자 안전·지속가능성 주장을 담은 경우를 빼면 텍스트 표시 규정 밖입니다[T2].

[elisha’s take] — ① EU 이용자에게 노출되는 생성형 기능을 모두 적어 놓고 8월 2일 전 출시분을 따로 표시합니다. 그 목록이 12월 2일 기한의 대상입니다. ② 각 기능에 기계 판독 표시가 실제로 들어가는지, 그 표시를 검출할 수단이 함께 제공되는지 둘로 나눠 확인합니다. 하나만 있으면 미이행입니다. ③ 공급사 모델의 워터마크와 자사 화면의 사람이 읽는 라벨을 분리해 설계합니다. 전자로 후자를 대신할 수 없습니다. ④ EU 현지 광고와 마케팅 자산에 AI 생성 이미지가 들어갔는지 점검합니다. 제품을 실제보다 좋아 보이게 만든 이미지가 딥페이크로 분류됩니다. ⑤ 해당 기능이 고영향 분류에 해당할 여지가 있으면 12월 2일 유예를 전제로 일정을 짜지 않습니다.

오픈소스 AI 침투테스트 도구를 공격자가 가져다 19곳을 노렸다 — 10곳에서 실제로 데이터가 나갔다

공격자가 오픈소스 AI 침투테스트 도구 Cairn을 개조해 8월과 9월에 작전 25건을 벌였습니다[T2]. Palo Alto Networks의 Unit 42가 11월 12일 공개한 보고서에 담긴 내용이고, 추적명은 CL-STA-1238입니다[T2]. 표적은 최소 19곳이고 그중 10곳에서 무단 접근이나 데이터 유출이 확인됐습니다[T2]. 쓰인 모델은 Zhipu GLM 5.2가 13건, DeepSeek V4 Flash가 8건, V4 Pro가 4건입니다[T2]. 모델 거부는 중국어 서두와 작전마다 만들어 둔 AUTHORIZATION.md 파일로 우회됐습니다[T2].

[elisha’s take] — 공격 기법은 그대로이고 범위만 넓어졌으므로, 자격증명 위생과 노출면 축소부터 다시 점검하십시오.

실제로 빠져나간 것 — 미국 교원노조에서는 계정 생성 우회로 유효 세션을 만들어, 회원 기록 100만 건 이상과 CRM 연락처 약 3만 1,000건, 직원 비밀번호 해시에 접근한 기록이 남았습니다[T2]. 산업 표준화 기구에서는 패스워드 스프레이로 유효 자격증명 수십 개를 얻고, 인증 없이 열린 클라우드 저장소로 진행 중인 표준 투표 문서를 덮어썼습니다[T2]. 반도체 기업에서는 운영 자격증명을 무작위로 맞혀 관리자 계정을 새로 만들고 지속형 API 토큰을 남겼습니다[T2]. 국방정책 프로그램에서는 열린 등록 창구로 이용자 약 500명의 기록이 드러났고 일부는 .mil과 .gov 주소였습니다[T2].

표적 구성과 작전 길이 — 반도체와 첨단 제조 공급망이 7곳, 국방과 국방정책이 3곳, 인권과 시민사회가 4곳입니다[T2]. 작전 한 건은 20분에서 50시간 넘게까지 걸렸습니다[T2]. Unit 42는 운영자 한 명이나 소수 팀이 돌린 것으로 판단했고, 중국 연계 정보수집으로 중간 신뢰도 평가를 내렸습니다[T2]. 공개된 Cairn에는 없는 AIScan Runner Skills 익스플로잇 모음이 더해져 있었고, 개조본은 홍콩 서버에서 돌았습니다[T2].

악용된 결함은 모두 재래식이다 — 인증 우회와 안전하지 않은 직접 객체 참조, 대량 할당을 이용한 권한상승이 쓰였습니다[T2]. 약하거나 기본값인 자격증명과 노출된 클라우드 API, 오래된 공개 CVE도 함께 동원됐습니다[T2]. Unit 42는 자율 AI가 악용의 양과 범위를 늘렸을 뿐 기술 난도를 올리지는 않았다고 결론지었습니다[T2]. 그래서 자격증명 위생과 노출면 축소, 패치가 여전히 통한다고 적었습니다[T2]. 반도체 장비 공급사 작전에는 여러 사업장의 VPN 게이트웨이 주소와 그룹명, 공유 암호가 미리 입력돼 있어 사전 정찰이 선행된 흔적이 보입니다[T2]. 침해지표는 홍콩 서버 154.44.31[.]4와 미국 경유 노드 82.29.129[.]54입니다[T2].

[elisha’s take] — ① 외부에 열린 등록·계정 생성 창구를 찾아 인증 없이 세션이 만들어지는지 직접 시험합니다. 교원노조와 국방정책 프로그램이 모두 이 경로로 뚫렸습니다. ② 운영 계정에 패스워드 스프레이 방어가 걸려 있는지 확인합니다. 잠금 정책과 속도 제한이 없으면 수십 개가 한 번에 나갑니다. ③ 관리자 계정과 장기 API 토큰 목록을 받아 모르는 항목을 폐기합니다. 공격자가 남긴 지속형 토큰은 패치로 사라지지 않습니다. ④ 인증 없이 열린 클라우드 저장소와 API를 전수 조사합니다. 표준 투표 문서가 이 경로로 덮어써졌습니다. ⑤ 침해지표 두 개를 방화벽과 프록시 로그에서 역추적합니다. 반도체·국방 공급망에 걸쳐 있으면 우선순위를 올립니다.

훔친 API 키로 Claude Code가 원격조종 임플란트가 됐다 — 명령은 메모리 스토어로, 데이터는 Files API로 나갔다

Darktrace가 11월 12일 실험 결과를 내놨습니다[T2]. 개발자 단말에서 Claude 자격증명을 확보한 공격자가 Claude 플랫폼의 메모리 스토어를 명령·제어 통로로, Files API를 유출 통로로 썼습니다[T2]. 모든 통신이 api.anthropic.com을 지나가므로 코딩 에이전트의 평소 추론 호출과 구분되지 않았습니다[T2]. 실험에서는 systemd 서비스가 권한 확인을 건너뛰는 옵션으로 Claude Code를 반복 실행했고, 작업 9건으로 내부망을 파악해 1GB 파일을 세 조각으로 나눠 올렸습니다[T2]. Darktrace는 플랫폼 취약점이 아니라고 밝혔고 실제 악용 사례는 확인되지 않았습니다[T2].

[elisha’s take] — 표준 API 키는 메모리 스토어에 닿지만 OAuth 자격증명은 닿지 않으므로, 에이전트 인증을 OAuth나 아이덴티티 페더레이션으로 옮기십시오.

메모리 스토어가 명령 통로가 된 방식 — 메모리 스토어는 Claude Console 워크스페이스에 붙는 텍스트 파일 모음입니다. 연구팀은 Claude Managed Agents를 쓰지 않는 조직에서도 API로 추가할 수 있었다고 밝혔습니다[T2]. 스토어에는 체크인용 heartbeat 파일, 작업을 적는 input 파일, 결과를 받는 output 파일 세 개를 뒀습니다[T2]. 새로 뜬 Claude Code 프로세스가 체크인하고 작업을 읽어 실행한 뒤 결과를 올립니다[T2]. 운영자는 평범한 문장으로 작업을 적고 명령은 모델이 알아서 만들었습니다[T2].

작업 9건이 지나간 경로 — 모의 사내 Active Directory 환경에서 에이전트가 내부망 구성을 파악했습니다[T2]. 익명 FTP 공유에서 직원 이름과 비밀번호 하나를 가져와 후보 사용자명 190개를 만들었습니다[T2]. 그 비밀번호를 도메인 컨트롤러에 뿌려 일치하는 계정을 찾아냈습니다[T2]. 이어 SMB 공유 목록을 뽑고 1GB 파일을 내려받아 세 조각으로 쪼갠 뒤 Files API로 올려 앤트로픽 서버 쪽으로 데이터를 빼냈습니다[T2].
