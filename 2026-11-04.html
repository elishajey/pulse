중요도 높음 위협 인텔리전스 보고 · 실제 침해 대응 사례

훔친 클라우드 키로 남의 AI 모델을 돌렸다 — 하루 요금 10만 달러, 누적 청구는 최대 100만 달러

구글 위협 인텔리전스 그룹(GTIG)과 Mandiant가 11월 3일 LLMjacking 대응 사례를 공개했습니다. 훔친 클라우드 자격증명으로 피해 기업의 AI 모델을 대신 쓰는 수법입니다[T1]. 올해 북미·남미·아시아태평양의 금융·유통·기술·운송 기업에서 하루 요금이 10만 달러를 넘은 사건이 있었고, 접근을 끊기 전까지 누적 100만 달러가 청구된 곳도 있었습니다[T1]. 재판매 서비스 Jet Night 한 곳은 8시간이 안 되는 동안 API를 50만 회 넘게 호출해, 피해 기업에 100만 달러 가까운 토큰 비용을 떠넘겼습니다[T1]. 이 서비스의 무제한 요금제는 월 60달러로 정상 요금(월 100~250달러)보다 싸서, GTIG는 훔친 키 없이는 이익이 날 수 없다고 판단했습니다[T1]. 가장 많이 쓰인 침입 경로는 노출되거나 도난된 클라우드 토큰입니다[T1].

[elisha’s take] — 꺼 둔 AI 서비스가 켜지는 순간부터 경보로 잡으십시오. 여러 사례에서 공격자는 꺼져 있던 모델 서비스를 훔친 키로 다시 켰습니다.

자세히 보기

돈이 새는 구조 — 침입과 판매가 분업돼 있습니다. 한쪽이 기업 환경에 들어가 키를 확보하면, ‘LLM 믹서’라 불리는 중계 서비스가 그 접근권을 모아 지하 구독자에게 되팝니다[T1]. 요금은 피해 기업이 내고 수익은 공격자가 가져갑니다. GTIG는 같은 이유로 범죄자들이 암호화폐 채굴보다 LLMjacking을 택하게 될 것으로 내다봤습니다[T1].

들키지 않으려는 수법 — 공개 GitHub 저장소에서 모은 API 키는 출력 토큰을 1개로 제한한 요청으로 유효성만 확인해 탐지 임계값을 피했습니다[T1]. UNC6993은 잘못 설정된 서비스 계정 키로 들어가 10만 달러 넘는 요금을 쌓았고, 가짜 포털에서 사용자의 활성 토큰을 받아 비밀번호와 MFA를 건너뛰었습니다[T1]. 내부 호스트를 흉내 낸 유사 도메인으로 접근권을 재판매 사이트에 넘긴 사례도 있었습니다[T1].

모델 게이트웨이도 뚫린다 — 한 공격자는 LiteLLM 게이트웨이의 CVE-2026-40217을 악용해 일반 가상 키를 관리자 키(PROXY_ADMIN)로 바꿨습니다. 키 재발급 엔드포인트에서 사용자 ID를 바꿔 끼울 수 있는 결함입니다[T1]. 보고서에 CVSS 점수가 없어 심각도는 확인하지 못했습니다[T3]. 공격자들은 침입 뒤 저장소와 DB에서 자격증명을 더 찾았고, 청구 최적화 도구로 위장한 백도어 계정도 만들었습니다[T1].

[elisha’s take] — ① 클라우드 감사 로그에서 AI 서비스 활성화와 모델 호출 이벤트를 IaC 계정이 아닌 주체가 일으키면 고위험 경보로 올립니다. 로깅 설정을 지우는 호출도 같은 등급으로 봅니다. ② 모델별 API 할당량과 지출 상한을 겁니다. 상한이 없으면 하루 만에 10만 달러가 나갈 수 있습니다. ③ 사내 LLM 게이트웨이를 취약점 관리 대상에 넣고, LiteLLM을 쓰면 CVE-2026-40217 패치 여부부터 봅니다. ④ 저장소 비밀 스캔에 AI API 키 패턴을 추가합니다. 공격자는 공개 저장소에서 키를 수집합니다.

중요도 높음 배포판 권고 · Ubuntu 수정 중

AI가 공격 코드를 만든 리눅스 커널 결함, CVSS 9.8 — Ubuntu는 아직 수정 커널을 내지 못했다

리눅스 커널의 IPv4 TCP 연결 처리에서 해제된 메모리를 다시 쓰는 결함 CVE-2026-98432가 공개됐고, 커널 CVE 팀은 CVSS 9.8을 매겼습니다[T1]. 앤트로픽 Frontier Red Team은 미공개 연구 모델이 이 결함으로 공격 코드를 약 53분 만에 만들었다고 밝혔습니다. MPTCP 리스너가 열린 서버에서 KASLR을 우회해 root 권한으로 명령을 실행했습니다[T2]. 결함은 커널 4.4부터 있었고 상위 커널에서는 이미 고쳐졌습니다[T2]. Ubuntu는 다릅니다. 11월 3일 보안 페이지에서 22.04·24.04·26.04 LTS와 26.10은 ‘수정 중’이고, 16.04~20.04 LTS는 수정 버전 표시 없이 취약 상태입니다[T1]. Debian·Amazon Linux·SUSE·Oracle Linux는 일부 커널의 수정본을 냈고, 실제 악용은 아직 보고되지 않았습니다[T2].

[elisha’s take] — MPTCP를 끄는 것만으로는 막히지 않습니다. 일반 TCP로도 결함이 건드려지니, 수정 커널이 나올 때까지는 접근 제한과 패킷 필터로 버텨야 합니다.

자세히 보기

Go 서비스를 먼저 봐야 하는 이유 — Go 1.24 이상은 커널이 지원하면 TCP 리스너에 MPTCP를 기본으로 켭니다[T2]. 운영자가 MPTCP를 쓴다고 생각하지 않는 서버에서도 앤트로픽이 시연한 조건이 갖춰질 수 있습니다[T2].

심각도 평가가 엇갈린다 — Red Hat은 같은 결함에 5.9점을 주고, 악용이 복잡하다며 서비스 거부 가능성 위주로 분류했습니다[T2]. 원격 코드 실행은 MPTCP 리스너가 있는 서버에서만 시연됐고, 앤트로픽은 공격 코드와 시험한 커널 버전을 공개하지 않았습니다[T2]. 그래서 패치 순서는 MPTCP 노출 여부로 나눠 정합니다.

실패해도 서버가 죽지 않는다 — 국내 보도에 따르면 공격이 실패해도 핸드셰이크만 깨지고 커널 패닉은 나지 않습니다. 공격자가 들키지 않고 여러 번 다시 시도할 수 있다는 뜻입니다[T3]. 서버가 멈추지 않으니 가용성 경보로는 이 공격을 알아채지 못합니다[T3].

[elisha’s take] — ① 외부에 열린 리눅스 서버 가운데 MPTCP 리스너가 있는 곳과 Go 1.24 이상으로 빌드한 서비스를 먼저 추립니다. ② Ubuntu 서버는 수정 커널이 나오는 즉시 적용할 수 있게 재부팅 일정을 미리 잡아 둡니다. ③ 그때까지는 신뢰하는 대역만 접속을 허용하고, IP 옵션이 붙은 IPv4 TCP 패킷을 nftables로 막는 CIQ 권고안을 검토합니다. ④ 수정 버전이 표시되지 않은 16.04~20.04 서버는 교체 일정부터 정합니다.

중요도 중간~높음 연구자 공개 · 수정 계획 없음

코딩 에이전트가 지원 끝난 MCP 서버를 알아서 골라 설치한다 — 한 주 다운로드 62만 회, 결함은 고쳐지지 않는다

Glow Security가 11월 2일 코딩 에이전트의 실제 세션 기록을 분석한 결과를 공개했습니다. 에이전트가 학습 데이터에 남아 있는 지원 종료 MCP 서버를 골라 개발자 PC에 설치하고 있었습니다[T2]. 지원 종료 서버가 설치된 세션의 98%에서 사용자는 그 패키지를 지정하지 않았습니다[T2]. @modelcontextprotocol 아래 지원 종료 패키지 12개는 10월 27일~11월 2일 한 주에만 npm에서 62만 838회 다운로드됐습니다(CI·미러 포함)[T2]. Glow는 이 서버들에서 고위험 결함 4개를 찾았습니다. 가장 심각한 Puppeteer 서버 결함은 웹페이지에 심은 프롬프트 인젝션으로 브라우저 대신 임의 프로세스를 띄웁니다[T2]. 유지보수 측은 보관 처리된 저장소라 고치지 않겠다며 보고를 닫았고, 결함에는 CVE도 없습니다[T2].

[elisha’s take] — CVE가 없어 의존성 점검 도구에 잡히지 않습니다. 개발 PC의 MCP 설정 파일을 직접 열어 @modelcontextprotocol/server-* 항목부터 찾으십시오.

자세히 보기

특정 도구만의 문제가 아니다 — Claude Code, Cursor, Codex CLI 등에서 앤트로픽·오픈AI·xAI 모델이 모두 같은 행동을 보였습니다[T2]. 한 에이전트는 npm에서 ‘지원 종료’ 표시를 확인하고도 그대로 설치했습니다[T2]. 개발자가 웹 브라우징만 허용해도 그 승인 범위 안에서 임의 명령이 실행되므로, Puppeteer 결함은 하네스의 승인 장치로 막지 못합니다[T2].

기존 도구가 못 보는 이유 — 이 서버들은 프로젝트 의존성 목록에 올라가지 않고 npx로 바로 실행됩니다[T2]. CVE가 없으니 소프트웨어 구성 분석(SCA)이 놓치고, EDR은 공개 npm 패키지를 평범하게 설치한 것으로 기록합니다[T2]. npm은 주간 다운로드 300회 미만에 소유자가 한 명뿐인 패키지만 내릴 수 있어, 이 패키지들은 계속 설치됩니다[T2].

공개 경위 — Glow는 7월 30일 HackerOne으로 처음 보고했으나 범위 밖이라는 답을 받았습니다. 10월 4~11일 결함 4개를 앤트로픽 CNA에 다시 보고했지만, 유지보수 측은 10월에 수정 계획이 없다며 권고를 닫았습니다[T2]. 실제 악용은 아직 확인되지 않았습니다[T2].

[elisha’s take] — ① 개발 PC의 MCP 설정에서 지원 종료 서버를 찾아 서비스 제공사의 공식 서버로 바꿉니다. GitHub·Slack·Postgres 서버가 다운로드 상위입니다. ② 서비스마다 승인된 MCP 서버를 하나로 정해, 에이전트가 임의로 고르지 못하게 합니다. ③ MCP 서버 승인 절차에 npm 지원 종료 여부 확인을 넣습니다. ④ 에이전트 하네스가 지원하는 실행 전 훅으로 지원 종료 패키지 설치를 막습니다.

모니터랩이 위협 인텔리전스 플랫폼 AI랩스 v6.0을 냈습니다[T2]. 흩어진 침해지표를 노드와 연결선으로 묶어 공격 흐름을 한 화면에서 따라가게 했고, 찾아낸 위협을 MITRE ATT&CK 전술·기법에 자동으로 연결합니다[T2]. 대화형 봇에 악성 도메인의 위험도와 대응 방안을 물을 수도 있습니다. 학습 데이터는 2억 5,000만 건이고, 결과는 KISA C-TAS와 VirusTotal 데이터로 검증한다고 회사는 설명했습니다[T2].
Novee — 잊힌 외부 노출 자산을 찾아 바로 모의침투까지 돌리는 기능 [T2 · 2026-11-03 공개]
