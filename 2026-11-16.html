중요도 높음 벤더 사후분석 공개 · 영향 범위 수치 제시

침해의 출발점은 Cursor가 아니라 협력사에 맡긴 키였다 — 그 키로 Claude Code 확장이 11시간 동안 갈아끼워졌다

Cursor가 11월 13일 10월 침해의 사후분석을 공개했습니다[T2]. 시작은 추론 협력사 Fireworks AI에 발급한 접근 키가 협력사 쪽에서 노출된 일이었습니다[T2]. 공격자는 그 키로 공유 스토리지를 열어 2025년 에이전트 대화 기록을 복사했고, 일부에 가림 처리가 빠진 자격증명이 남아 있었습니다[T2]. 그 자격증명으로 내부 도구까지 들어가 10월 29일 Claude Code 확장 조작본 2.1.312·2.1.313을 마켓플레이스에 올렸습니다[T2]. 조작본은 약 11시간 노출돼 최대 5,000명이 다운로드할 수 있었고, Cursor는 대화 기록 노출 0.05% 미만·자격증명 노출 고객 0.01% 미만이라고 밝혔습니다[T2].

[elisha’s take] — 10월 29일에 Cursor 마켓플레이스에서 Claude Code 확장을 설치하거나 갱신한 적이 있으면 버전을 확인하고, 그 단말에서 쓴 토큰과 API 키를 교체하십시오.

자세히 보기

협력사 침해가 고객사까지 번졌다 — 11월 11일 호에서 Fireworks AI가 침해 범위를 환경 변수에서 모델 가중치까지 넓혀 공지한 건을 다뤘습니다. 이번 Cursor 발표는 그 침해가 고객사 쪽에서 어디까지 번졌는지를 처음으로 수치와 함께 보여준 후속입니다[T2]. 협력사 쪽 경과는 이렇습니다. 10월 23일 Fireworks 연구용 장비를 호스팅한 클라우드 사업자에서 사고가 있었고[T3], 10월 24일에는 무단 접근이 Fireworks 개발 장비까지 이어졌습니다[T3].

학습용으로 넘긴 기록에 자격증명이 섞여 있었다 — 반출된 대화 기록은 Privacy Mode를 끈 세션에서 나온 것으로, 모델 학습에 쓰도록 허용된 데이터였습니다[T2]. 대부분 2025년 기록이고 일부에 가림 처리가 빠진 자격증명이 들어 있었습니다[T2]. 학습 허용 데이터를 협력사와 공유하는 구조에서는 가림 처리 실패 하나가 곧 침해 경로가 됩니다[T2]. 언론 보도에 따르면 공격자는 내부 도구에서 보관 저장소와 지원 데이터, 사용 지표에 접근했습니다[T3].

영향을 받지 않은 범위 — Cursor는 영향이 없는 범위를 따로 들었습니다[T2]. 서비스를 돌리는 프로덕션 시스템과 기반 설비·공식 애플리케이션 릴리스가 여기 들어갑니다[T2]. 고객 코드 저장소와 Privacy Mode를 켠 이용자의 코드·프롬프트도 영향이 없다고 덧붙였습니다[T2]. 마지막으로 관측된 공격 활동은 11월 1일이며 차단됐습니다[T2].

대응 — 추론 트래픽을 전량 Fireworks 밖으로 옮기고 협력사 키를 폐기했으며, Fireworks와 공유한 모든 데이터셋의 접근을 끊었습니다[T2]. 노출된 자격증명을 폐기·교체하고 확장 마켓플레이스를 다시 만들었으며, 예방 조치로 프로덕션 기반 설비를 재배포했습니다[T2]. 어느 사업자가 추론을 대신 맡았는지, Fireworks가 다시 들어올지는 밝히지 않았습니다[T2]. 보도된 세부 가운데 하드웨어 보안모듈 서명 의무화와 48시간 탐지 구간은 다른 매체에서 확인되지 않았습니다[T3].

프레임워크로 보면 — MITRE ATLAS에서는 협력사 경유 초기 접근과 유효 계정 획득이 이어진 형태입니다[T2]. OWASP LLM Top 10에서는 LLM03 공급망과 LLM02 민감정보 노출에 함께 해당합니다[T2]. 확장 배포 단계만 보면 개발자 도구 공급망 공격이지만, 자격증명이 학습 데이터에 섞여 들어가 AI 특유의 고리가 생겼습니다[T2].

[elisha’s take] — ① 개발자가 쓰는 AI 코딩 도구의 확장 버전을 자산 목록에 올리고 10월 29일 설치·갱신 이력을 조회합니다. 확장을 지우는 것만으로는 끝나지 않습니다. ② 학습 허용 설정을 재검토합니다. Privacy Mode를 끈 세션의 대화가 협력사 스토리지로 넘어가는 경로가 이번 출발점이었습니다. ③ 에이전트 대화 기록에 자격증명이 들어가지 않게 입력 단계에서 가립니다. 사후 가림은 이미 복사된 기록에 닿지 않습니다. ④ AI 도구 협력사에 발급한 키의 범위와 수명을 줄이고, 데이터셋 접근권을 키와 분리합니다. ⑤ 침해 통지에서 ‘프로덕션 영향 없음’과 ‘데이터 영향 없음’을 구분해 읽습니다. 이번 건은 전자가 참이고 후자가 거짓이었습니다.

중요도 중간~높음 보안기업 조사 공개 · 도메인 목록 기준

AI 서비스 주소를 한 글자 잘못 치면 가짜 보안 확인 창이 떴다 — 도메인 186개가 AI 브랜드 27곳을 사칭했다

Island가 11월 12일 AI 브랜드 27곳을 사칭한 유사 도메인 186개를 찾아 공개했습니다[T2]. 이 수법을 TypoPrompting이라고 불렀고, 사칭 대상은 ChatGPT 25개·Claude 18개·DeepSeek 16개·Runway 12개 순입니다[T2]. 한 갈래는 가짜 Cloudflare 확인 화면으로 Windows 이용자가 PowerShell 명령을 직접 실행하게 만드는 ClickFix입니다[T2]. 나머지 두 갈래는 보안 점검 앱으로 위장한 Net Guard와 검색 결과를 가로채는 브라우저 확장입니다[T2]. 확인된 확장 30개 가운데 13개는 삭제됐고 17개는 아직 남아 있으며 이용자 97만 2,000명이 쓰고 있습니다[T2].

[elisha’s take] — 사내 프록시에서 주요 AI 서비스 도메인의 유사 변형을 차단 목록에 올리고, 브라우저 확장은 관리자 허용 목록으로 제한하십시오.

자세히 보기

세 갈래 경로 — 첫째는 ClickFix입니다. 가짜 Cloudflare 확인 화면을 띄워 ‘사람인지 확인’ 절차처럼 보이게 하고, 이용자가 직접 PowerShell 명령을 붙여 실행하도록 유도합니다[T2]. 사용자가 손으로 실행하므로 다운로드 차단에 걸리지 않습니다[T2]. 둘째는 Net Guard라는 이름의 앱으로, 보안 점검 도구처럼 보이게 꾸몄습니다[T2]. 셋째는 검색을 가로채는 브라우저 확장입니다[T2]. 일부 도메인은 악성 사이트가 아니라 광고 페이지로 넘깁니다[T2].

남아 있는 확장 17개가 문제다 — 확장 30개 중 13개만 삭제됐고 17개는 그대로 있습니다[T2]. 그 17개를 쓰는 이용자가 97만 2,000명이므로, 도메인을 차단해도 이미 깔린 확장은 남습니다[T2]. 도메인 차단과 확장 점검을 같이 해야 하는 이유입니다[T2].

수치의 성격 — Island는 186개가 발견한 도메인을 모은 목록일 뿐 감염이 확인된 수는 아니라고 못 박았습니다[T2]. 지금까지 이 활동으로 생긴 피해액도 확인되지 않았습니다[T2]. 보도 사이에 차이가 있습니다[T3]. The Hacker News는 사칭 대상으로 Anthropic Claude·OpenAI ChatGPT·Google Gemini·Cursor를 들었습니다[T3]. 다른 매체는 상위 브랜드에 Runway를 올렸습니다[T3].

왜 AI 브랜드인가 — AI 서비스는 주소를 직접 입력해 들어가는 비중이 높고, 신규 도메인이 자주 생겨 이용자가 진짜와 가짜를 구별할 기준을 갖기 어렵습니다[T2]. 가짜 확인 화면이 보안 절차처럼 보이기 때문에 이용자는 더 쉽게 속습니다[T2]. MITRE ATLAS로 보면 AI 공급망이 아니라 이용자를 노린 초기 접근 계열이며, 모델이 아니라 사람과 브라우저가 표적입니다[T2].

[elisha’s take] — ① 사내에서 쓰는 AI 서비스의 정식 도메인 목록을 만들고, 한 글자 변형과 하이픈 변형을 프록시 차단 목록에 넣습니다. ② 브라우저 확장을 관리자 허용 목록으로 제한하고, 검색 결과를 바꾸는 권한을 요구하는 확장을 먼저 걸러냅니다. ③ ClickFix 대응으로 엔드포인트에서 클립보드 붙여넣기로 시작하는 PowerShell 실행을 탐지 규칙에 넣습니다. ④ 이용자 안내에 ‘보안 확인 화면이 명령 실행을 요구하면 그 자체가 공격’이라는 한 줄을 넣습니다. ⑤ 이미 깔린 확장을 조회합니다. 도메인만 막으면 남은 17개는 계속 동작합니다.

중요도 중간 재단 프로젝트 출범 · 규격 초안 단계

에이전트에 도메인으로 신분을 붙이는 규격이 재단 프로젝트가 됐다 — 조직이 이미 가진 도메인과 인증서를 그대로 쓴다

Linux Foundation이 6월 설립 의향을 알린 Agent Name Service(ANS)가 11월 10일 재단 프로젝트로 출범했습니다[T2]. DNS와 웹사이트가 쓰는 인증서를 그대로 활용해 AI 에이전트에 신분·검증·탐색을 붙이는 공개 표준입니다[T2]. 별도 네임스페이스를 사지 않고 조직이 이미 보유한 도메인으로 에이전트를 식별합니다[T2]. 이름에 버전을 함께 담으므로 새 버전은 새로 등록해야 합니다[T2]. 규격은 7개 문서로 이뤄지고 Cisco·Cloudflare·DigiCert·OWASP 등 11곳이 참여했거나 채택했습니다[T2].

[elisha’s take] — 규격은 아직 초안이므로 도입을 서두를 단계는 아닙니다. 다만 에이전트를 어느 도메인 아래 둘지는 지금 정해 두십시오. 나중에 이름 체계를 바꾸려면 비용이 훨씬 큽니다.

자세히 보기

규격이 다루는 범위 — 다섯 갈래입니다[T2]. 도메인을 기준으로 삼은 이름 체계와 등록·버전 관리가 첫째고[T2], DNS를 통한 신분 공표와 신분 검증 절차가 그다음입니다[T2]. 공개 로그 감사와 무결성 감시, 에이전트 사이 인증이 나머지입니다[T2]. 공개 로그 감사는 신분 기록이 몰래 바뀌는 것을 탐지하는 장치입니다[T2]. 이름 형식은 버전을 도메인에 붙인 꼴로, ans://v1.0.0.payments.example.com 같은 모양입니다[T2]. 검증 세부 절차는 보도자료 수준에서는 공개되지 않았습니다[T3].

출범 자리와 운영 주체 — 출범은 11월 10일 솔트레이크시티에서 열린 KubeCon + CloudNativeCon North America에서 발표됐습니다[T2]. 프로젝트는 Linux Foundation 기술운영위원회가 관리합니다[T2]. 참여하거나 채택한 조직은 11곳이며 네트워크·인증서·도메인 사업자가 다수입니다[T2]. Cisco·Cloudflare·DigiCert·GoDaddy·Infoblox·Radix·Salesforce가 여기 속합니다[T2]. 나머지는 DistributedApps.ai·HOL·Trustmodel.ai와 OWASP입니다[T2].

초안이라는 점을 빼놓지 말 것 — 보도자료는 규격이 정식화됐다고 적었지만, 프로젝트 문서의 규격은 여전히 개발 중인 초안으로 표시돼 있습니다[T3]. ANS-6 문서는 2026년 11월 3일자 DRAFT v1.0, 버전 0.2.0입니다[T3]. 일부 매체가 ANS를 개발 표준이라고 부른 것도 이 차이에서 나옵니다[T3]. 코드와 규격은 github.com/agentnameservice에, 프로젝트 정보는 ansinfo.ai에 있습니다[T2].

주변 프로젝트와 맞물리는 지점 — 같은 재단의 AGNTCY Agent Directory Service가 ANS 신분 검증을 지원합니다[T2]. ANS Finder는 Agentic Resource Discovery 규격을 구현하고 레지스트리 적합성 시험을 통과했습니다[T2]. 초기 개발을 이끈 DistributedApps.ai의 Ken Huang이 기술운영위원회에 들어갈 예정입니다[T2].

국내 관점 — 11월 15일 호에서 다룬 한국인터넷진흥원의 에이전틱 AI 제로트러스트 안내서는 에이전트의 행동마다 인증을 걸라고 요구합니다[T2]. 그 요구를 실제로 구현할 때 ‘무엇으로 에이전트를 식별할 것인가’가 빈칸으로 남는데, ANS는 그 빈칸을 도메인과 인증서로 채우려는 시도입니다[T2]. 다만 두 문서가 서로를 참조하지는 않으므로, 이 연결은 기능상 대응 관계이며 제도상 연계는 아닙니다[T2].

[elisha’s take] — ① 사내 에이전트를 어느 도메인 아래 둘지와 버전을 이름에 넣을지 지금 정합니다. 이름 체계는 나중에 바꾸기가 가장 비쌉니다. ② 에이전트 식별을 공유 API 키에 의존하는 구간을 찾아 목록으로 만듭니다. 키는 주체를 구분하지 못합니다. ③ 인증서 발급·폐기 절차에 에이전트를 포함할 수 있는지 확인합니다. ANS는 기존 인증서 체계를 전제로 합니다. ④ 규격이 초안인 동안에는 시험 환경에서만 다룹니다. ANS-6은 버전 0.2.0입니다. ⑤ 에이전트 사이 호출 로그에 호출자 신분을 남기도록 지금 고쳐 둡니다. 신분 체계가 바뀌어도 이 로그는 그대로 쓰입니다.
